## Step 5 -- Health check does not verify database reachability

**Requirement:** "Health check. Call GET /health on staging. It must return 200 and report that the database is reachable. A plain 200 is not enough, because the process can be up while the DB connection is dead."

**Gap:** `src/routes/health.js` returns `{ status: 'ok' }` unconditionally. It performs no database query and does not include any field that indicates whether the database is reachable. The `health_check_staging` gate check will always FAIL against the current implementation because it looks for a `db` field (or equivalent) in the response body to satisfy the runbook's "report that the database is reachable" requirement.

**Evidence:**
- `src/routes/health.js:4-5` -- `res.json({ status: 'ok' })` — static response, no DB probe

**Suggested remediation:** Update `src/routes/health.js` to execute a lightweight DB query (e.g. `SELECT 1`) using the `db` singleton from `src/db.js`. On success, respond with `{ status: 'ok', db: 'ok' }`. On failure, respond with HTTP 503 and `{ status: 'error', db: 'unreachable' }`. This change is in application code (`src/`) and must be made by the development team.

## Step 6 -- Smoke script missing create-shift flow

**Requirement:** "Smoke tests. Run the smoke suite against staging. It has to cover the three flows customers use most: logging in, creating a shift, and listing shifts. All three must pass."

**Gap:** `scripts/smoke.js` tests only two of the three required flows (login and list shifts). It does not test the "creating a shift" flow (`POST /shifts`). The `smoke_tests` gate check runs `npm run smoke` and verifies from its output that all three named flows appeared and passed. Because the create-shift flow is absent from `scripts/smoke.js`, the gate will FAIL with `"create shift" did not run (not present in smoke suite output)` until the script is updated.

**Evidence:**
- `scripts/smoke.js:31-38` -- only `list shifts` is checked after login; the file closes the server immediately after without any `POST /shifts` call

**Suggested remediation:** Add a third `check('create shift', ...)` block to `scripts/smoke.js` that calls `POST /shifts` with a valid JWT and asserts HTTP 201. This is a change to `scripts/smoke.js`, which is not under `src/`, `test/`, or `migrations/` and may be edited without touching application code.
